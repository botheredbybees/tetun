# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static, client-side browser game for learning Tetun (Timor-Leste). No build step, package manager, linter or test suite. Everything is plain HTML/CSS/JS with vendored libraries (jQuery 1.11, jQuery UI, Bootstrap 3, jquery.cookie, touch-punch).

To run it, serve the folder and open it in a browser:

```bash
python3 -m http.server 8000   # http://localhost:8000
```

Opening `index.html` directly also works. Verification is manual, by playing a lesson in the browser.

## Architecture

All logic is in `js/main.js` (global scope, no modules). `index.html` is a shell: an empty `#container`, a navbar `.pagination`, and two Bootstrap modals (`#matchingGame`, `#successMessage`). Both the lesson menu and the pagination list are generated by JS on `document.ready`.

**Three parallel arrays define the content and must stay index-aligned:**

- `CueCards[n]` is lesson `n`, an array of `[tetun, english, 0]` triples.
- `units[n]` is `[tetun topic name, english lesson title, icon key]`, used for the modal title.
- `topics[t]` is `[tetun name, english name, icon key, pageCount]`. The menu is built by walking `topics` and consuming `pageCount` consecutive lessons each, so the sum of all `pageCount` values must equal `CueCards.length`.

The icon key selects `images/<key>_{disabled,finished,ninja}.png`, so a new topic needs all three images.

**Game flow** (`init(page)` -> `handleCardDrop`):

- A lesson starts with 1 pair (`words2show`) and each fully matched round adds one, up to 10. `init` re-deals from the same shuffled `getCards` until `words2show` resets to 1.
- The drag direction alternates each round through the global `direction` (`t2e` / `e2t`).
- Scoring: a correct drop adds about 1.818 points (100 divided by 55, the total of rounds 1 to 10) and a wrong drop costs 1, capped at 100.
- The game's end is hardcoded as `correctCards == 10`. Every lesson in `CueCards` must have exactly 10 pairs, or the lesson can't be completed or finishes wrongly. All 33 lessons currently have 10.
- On completion, the score maps to a `progressArray[currentPage]` level: 1 (under 50%), 2 (50-69), 3 (70-98), 4 (99-100, "ninja"). The menu icons and CSS classes (`finished`, `ninja`, `ui-icon` for disabled) are updated in place by swapping the `src` suffix.

**Persistence:** progress is a JSON array in a single `progress` cookie (`$.cookie`, `expires: 356` days) with one level per lesson. If the cookie is missing it is initialised to zeros sized to `CueCards.length`. If the cookie was saved when there were fewer lessons, it is not padded, so new lessons read as `undefined` and display as unstarted.

## Gotchas

- `README.md` is stale on counts. It says 11 topics and 31 lessons, but the code has 12 topics (including `Ita haan lai!` / eat), 33 lessons and 330 pairs.
- `draggable({ containment: '#content' })` refers to an id that doesn't exist in `index.html` (only a `#content` rule in `css/main.css`), so the containment is effectively unused.
- `shuffle()` has a broken type check, `typeof(cards[target] == 'object')`, which is always truthy. It works only because every element is an array or an array-like string, so don't pass it a non-sliceable array.
- `js/jquery.cookie.js` and `js/vendor/jquery.cookie.js` are the same file apart from a trailing newline. `index.html` loads the vendor copy.
- `index.html` tries jQuery from `http://code.jquery.com` first and falls back to the vendored copy. It also contains a hardcoded Google Analytics snippet (`UA-51638709-1`).
- `<title>` and the meta description in `index.html` are empty.
- `data/` holds source material only, not loaded at runtime: a Tetun-English lexicon (`.rtf` and the `Tetun - English/` Lexique Pro project), the LIFT XML spec PDF, and `tetun.csv` (garbled encoding) / `tetun2.csv` (cleaned). Vocabulary is hand-copied from these into `CueCards`.

## Conventions

- Tetun spelling matters: keep diacritics (e.g. `Númeru`). Files are UTF-8.
- Corrections to vocabulary come from Tetun speakers via issues and PRs, so edit `CueCards` entries directly rather than regenerating them.
